# ADR-0017: Backend Summary Archive Pipeline

Date: 2026-05-17

## Status

Accepted.

## Context

Tomato import currently creates book chapters and then uses a Dify reading archive route to produce `summary.md`.
That route is expensive, hard to treat as a fixed import job, and overlaps with the backend batch-pipeline pattern already
used for world/status and style initialization. The reading archive is not an author conversation surface: it is a
derived archive from imported chapters.

## Decision

First-create and explicit rebuild of `summary.md` are owned by the backend summary archive pipeline.

- Tomato import triggers a backend pipeline after chapters and `import_report.json` are committed.
- The pipeline reads `chapters/*.md`, produces batch archive sections, writes `summary.md`, updates summary metadata,
  and commits the changed archive artifacts.
- The bookshelf keeps using summary progress/status APIs, but those APIs report backend pipeline progress rather than
  Dify reading archive progress.
- The Dify `reading_archive_agent` app, route, and historical workflow runs become compatibility/audit evidence only.
  They must not be the active default summary generation path.

## Boundaries

- Dify workflows may read `summary.md` as context for world, style, outline, continuation, and review.
- Dify workflows do not own `summary.md` first-create/rebuild.
- The backend pipeline may summarize imported source chapters, but it must not generate novel continuation prose,
  outline cards, or author-facing story decisions beyond archival recap.
- Historical `summary.md` files generated by Dify remain valid book history.

## Compatibility

No schema migration, Dify database mutation, book workspace migration, or backfill is required for this decision.
Existing books keep their current `summary.md`; the new owner applies to future import summary generation and explicit
summary rebuild actions.

## Verification

- Architecture graph/index JSON parse.
- ER entities/relationships JSON parse.
- Import flow diagram shows backend summary archive pipeline instead of Dify reading archive batches.
- Later implementation must prove a completed summary write leaves the per-book Git repository clean and does not call
  Dify `reading_archive_agent`.
